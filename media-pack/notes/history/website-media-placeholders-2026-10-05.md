# 补充计划：声音、视频、三维、动作的占位（给 Codex）

> 用法：Codex 把本文件内容作为**附录 D** 并入 `docs/plans/active/2026-10-05-actors-and-launch.md`，
> 在 **P3** 里作为第 9 个单元完成；如果读到时已经过了 P3，就在 P5 全量验收之前做。不要中断正在做的单元。
> Owner 2026-10-05 提出，Claude 设计。

## 目的

两位演员以后还会有声音、视频（例如转身一圈）、三维模型和动作。现在都还没有，
但网站先把位置留出来，让来访的人知道"以后这里会有什么"，以后有了真文件直接填进去，不用再改版面。

## 规则

1. **诚实**：只写"规划中"。不放假的播放器、假波形、假的三维预览，不写上线日期，不写数量。
2. **平常话**（计划 D9）：每块一句话说明以后放什么。
3. **状态自动算**：某种媒介在清单里有文件，就显示"已开放"和数量；没有就显示"规划中"。不要手写开关。
4. **用 UIKit 现成组件**：说明块用 `GameEmptyState`，汇总用 `GameFactList`，状态用 `GameBadge`。
   UIKit 图标里没有麦克风、视频、立体方块、动作这几种，先统一用 `hourglass`（沙漏，表示"以后会有"）；
   报告里写一条给 UIKit 的上游请求：新增 `mic`、`video`、`cube`、`motion` 图标。以后有了，只改一处映射。
5. **更少**：不新建页面；不做选择框、下载按钮；不加载三维或视频代码。

## 放在哪里、怎么排

**1. 演员档案页 `/[locale]/actors/[slug]`**：在图片预览那一节下面加一节"资料 / Materials"，用 `GameFactList` 列五行。

```text
资料
┌───────────────────────────────────────────┐
│ 图片        已开放 · 63 张        查看 →  │  ← 绿色徽章，链接到资产库
│ 声音        规划中                        │  ← 灰色徽章
│ 视频        规划中                        │
│ 三维模型    规划中                        │
│ 动作        规划中                        │
└───────────────────────────────────────────┘
```

手机上同样是一列，不需要另做布局。

**2. 资产库页 `/[locale]/kit/[slug]`**：在所有图片系列之后、"文字"一节之前，加一节"更多资料（规划中）/ More materials (planned)"，
`id="series-more"`，四个 `GameEmptyState` 排成两列（桌面）或一列（手机）。顶部的系列跳转里加一个"更多资料"入口。

```text
更多资料（规划中）
┌────────────────────┐  ┌────────────────────┐
│ ⌛ 声音             │  │ ⌛ 视频             │
│ 这里将放演员的声音  │  │ 这里将放演员的参考  │
│ 样本，可以在网页上  │  │ 视频，比如转身一圈、│
│ 试听，也可以下载。  │  │ 走路、表情变化。    │
└────────────────────┘  └────────────────────┘
┌────────────────────┐  ┌────────────────────┐
│ ⌛ 三维模型         │  │ ⌛ 动作             │
│ …                  │  │ …                  │
└────────────────────┘  └────────────────────┘
```

这四块不能被选中，也不出现在打包和拼图里。

**3. 其他页面不动**：首页、名册卡片、`/kit` 总览保持只算图片；资产页顶部的进度数字明确写"图片"。

## 以后真做的时候（只写进 spec，不实现）

在资产库 spec 末尾加一小节"后续媒介"，写清方向，免得以后各做各的：

- 流程和图片一样：文件放 `assets-inbox/<code>/`，入库命令校验，预览公开，母版放私有 Blob，下载规则（游客限速、会员不限）相同。
- 声音：母版 WAV，预览压成 AAC/MP3；网页用原生 `<audio>` 播放。
- 视频：母版 MP4（H.264）；预览是几秒的静音循环片段。
- 三维模型：GLB；网页预览用项目已有的 three.js 方案（`@react-three/fiber`、`drei`），压缩后的预览文件公开，原文件私有。
- 动作：动作片段（GLB 或 FBX），在三维模型上预览。
- 每种媒介的具体格位（比如声音要哪几段、视频要哪几条）等真有文件时，单独写计划定。
