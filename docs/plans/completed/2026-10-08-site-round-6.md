# 网站第六轮：演员身份与存档、声音视频、95 位新面孔、角色设定图、面向全球的文案

第五轮里与本计划冲突的几处已经在第五轮计划里改好（版本显示、编号、资产库的声音视频区块）。

全站文案以[文案稿](2026-10-08-site-copy.md)为准，**一字不改照抄**；需要新文案而稿里没有的，先停下问 Claude，不要自己写。

## 1. 身份：网站上不出现编号，文件按名字管理

Owner 不希望网站上出现 SP-13 这样的编号，文件名也不要编号。

### 1.1 规则

- **演员的唯一标识是 slug**：艺名的拼音或英文，小写，用连字符连接，例如 `tang-yunqiu`、`misha-luo`、`clara-vos`。
  - 网址、文件夹、文件名、云端存储路径、项目包都用它。
- **slug 一经发布永不改、永不复用。**
  - 艺名以后改了，slug 不跟着改。
  - 实在要改，就加永久跳转，旧 slug 留在跳转表里。
  - 新演员起名时就保证 slug 不重复；加一条测试检查。
- **文件命名**：`{slug}__{种类}__{格位}__v{大版本}.{扩展名}`，例如：
  - `tang-yunqiu__turnaround__front__v1.png`
  - `tang-yunqiu__wardrobe-maid__front__v1.png`
  - `tang-yunqiu__voice__intro__v1.wav`
  - `tang-yunqiu__video__turntable__v1.mp4`

  大版本号就是第五轮第 6 节的"第一位"。

- 网站上任何地方都不显示编号：卡片、演员页、资产库、分享卡片、图片 alt、复制块标题、ZIP 和 JSON 文件名都不显示。
  - 复制块标题改成"{名字} · 角色种子"。
- `Actor` 类型删掉 `code` 字段。
  - 依赖编号的逻辑全部改用 slug，包括入库正则、资产词表、测试、分享卡片、导出。
  - 编号和 slug 的对照只在迁移报告里留一份，代码里不留。

### 1.2 迁移现有内容

- **网站**：
  - 两位现役演员的清单、`public/media/assets/**` 文件名、私有 Blob 里的原图都改成新命名；
  - Blob 采用"上传新的 → 校验 → 再删旧的"；
  - 公开网址 `/media/**` 跟着清单走，不需要跳转。
- **项目包**：
  - `media-pack/cast/SP-13.json` 改成 `media-pack/actors/tang-yunqiu.json`（SP-03 同理）；
  - `media-pack/library/staging/SP-13/` 改成 `media-pack/library/actors/tang-yunqiu/staging/`；
  - `pack.json` 的路径和命名模板跟着改，`README.md`、`checks.md` 里的命名说明跟着改。
- **MediaFactory 兼容**：MediaFactory 用 `media-pack-1` 格式读项目包。
  - 先读 MediaFactory 的 `schema/media-pack.schema.json`；
  - 如果字段名写死了 `cast`，就保留字段名，只改路径；
  - 改完用 MediaFactory 的项目包校验命令跑一遍，结果写进报告。
- 张强、陈伟按第 5.4 节并入，一起迁移。

## 2. 存档：三个地方，各管一件事

Owner 的要求：版本升级时要拿得到旧版本的东西，但不要搞复杂。

| 地方                                                                 | 放什么                                                                         | 作用                                         |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------ | -------------------------------------------- |
| git（`media-pack/actors/<slug>.json`、`src/content/actors/<slug>/`） | 演员事实、提示词、声音描述、版本记录                                           | 文字的唯一来源，历史靠 git                   |
| Vercel Blob 私有库                                                   | 每个发布版本的全部原件（PNG、WAV、MP4），路径 `actors/<slug>/v<版本>/<文件名>` | 正式存档和云端备份，**发布过的版本永不删除** |
| 本机 `media-pack/library/actors/<slug>/`                             | 工作区：待入库、淘汰、试验                                                     | 只是工作副本；发布过的东西一定在 Blob 里     |

- **公开预览**：
  - 图片预览沿用现在的做法（放在 `public/media`，进 git）；
  - 声音和视频的预览文件比较大，放进**新的 Vercel Blob 公开库**，网站从清单读网址。
- **两个工具**：
  - `pnpm assets:pull <slug> [--version 1.0.0]`：把某个版本的原件从 Blob 下载到 `media-pack/library/actors/<slug>/<版本>/`，用于升级时拿旧版本。
  - `pnpm assets:ingest`：现有入库工具。扩展到声音和视频；入库时要求 `releases.ts` 里已经写好这个版本的记录，否则拒绝。
- **升版本的流程**：
  1. pull 当前版本；
  2. 在 staging 放新的或替换的文件；
  3. 写 release 记录；
  4. ingest；
  5. 发布。

  旧版本原件留在 Blob；网站只展示最新版；历史在版本记录里。

- 在 `docs/reference/release.md` 写一页"给演员升版本"的步骤。照着做就不会乱。

## 3. 版本号怎么显示（覆盖第五轮第 6.3 节）

- 演员页名字旁边、资产库页头各放一个小号版本标签 `v1.0.0`（中性 `GameBadge` 样式）。
- 点它弹出 `LiquidPopover`，标题"版本记录"，内容是：
  - 每个版本一行：版本号、日期、一两句改了什么，新的在上；
  - 底部一行小字解释三段数字（文案见文案稿）。
- **不再**在资产库页面放"版本记录"区块，演员页资料表也不放版本那一行。
- 新面孔用 `0.x` 版本：`0.1.0` 表示只有试镜照和一段声音。
  - 被选进项目、补齐全套资料后升到 `1.0.0`；
  - 弹窗里有一句话解释"0 开头 = 新面孔，还在试镜阶段"。

## 4. 资产库：图片、声音、视频都在同一页

Owner 要一页看全，不要点进声音再进一个页面。

### 4.1 页面顺序

1. 页头（第五轮）；
2. 吸顶跳转条：各图片系列 · 声音 · 视频 · 怎么用 · 文字资料 · 使用规则；
3. 图片各系列；
4. **声音**；
5. **视频**；
6. 怎么用；
7. 文字资料；
8. 使用规则。

第五轮页头那排"媒介状态"徽章删掉，因为声音、视频已经有自己的区块。

### 4.2 声音格位（每位演员 6 个基础格 + 每个角色造型 1 个）

| 格位          | 中文             | 内容                                                             | 用途                                                             |
| ------------- | ---------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------- |
| `intro`       | 自我介绍         | 用母语说 15–20 秒的自我介绍，自然口语                            | 最能代表这个人的一段；**同时是克隆用的参考音**，格子上标"参考音" |
| `intro-alt`   | 第二语言自我介绍 | 中文演员说英文，外国演员说中文（说不好也没关系，口音本身是特点） | 面向全球                                                         |
| `chat`        | 日常聊天         | 生活里随口说的一段                                               | 自然状态                                                         |
| `happy`       | 开心             | 开心、大笑                                                       | 情绪范围                                                         |
| `angry`       | 生气             | 生气、吼                                                         | 情绪范围                                                         |
| `sad`         | 难过             | 低落、想哭                                                       | 情绪范围                                                         |
| `role-<造型>` | 角色台词         | 穿着这个角色时说的一句戏里台词                                   | 和作品挂钩                                                       |

- 每格是一张卡片，包含：
  - 播放 / 暂停按钮（`GameIconButton`）；
  - 细进度条和时长；
  - 台词文字（可折叠，方便字幕和配音参考）；
  - 下载按钮，规则同图片：游客 30 秒一个，会员不限，ZIP 可以包含声音。
- 同一时间只播放一段。没交付的格位显示"规划中"，不可点。
- 文件规格：
  - 原件 WAV，存私有 Blob；
  - 预览 MP3 128k，存公开 Blob；
  - 下载给 WAV。

### 4.3 视频格位（每位演员 4 个基础格 + 每个角色造型 1 个）

| 格位          | 中文     | 内容                                             | 用途                      |
| ------------- | -------- | ------------------------------------------------ | ------------------------- |
| `turntable`   | 转台     | 基础装原地转一圈，8 秒，无声，透明或纯色底       | 做 3D、做一致性参考、截图 |
| `intro`       | 自我介绍 | 对着镜头说自我介绍那段话，口型对上声音，15–20 秒 | 最直观地认识这个人        |
| `walk`        | 走路循环 | 侧面走一个循环，4 秒，可以无缝循环               | 动画和合成参考            |
| `expressions` | 表情串   | 中性、笑、生气、惊讶、难过依次过一遍，8 秒       | 表演范围                  |
| `role-<造型>` | 角色片段 | 穿戏服演一小段，10–15 秒                         | 和作品挂钩                |

- 每格是一张卡片：
  - 显示封面图；
  - 点了在第五轮的灯箱里播放（灯箱支持视频；做不到就用原生 `<video>` 播放器，外观按 UIKit 包一层）；
  - 下载规则同上。
- 视频都还没有，这一轮全部按"规划中"占位。

## 6. 角色设定图（Owner 2026-10-08 新增）

把几张图拼成一张 16:9 的角色设定图（character sheet），和"下载全部资产"是两回事。

### 6.1 不新增依赖

仓库里已经有：

- 4K 拼图的排版：`features/assets/sheet-layout.ts`，3840×2160，自动选列数；
- 画布渲染：`render-sheet.ts`；
- 会员导出弹窗。

这几样在这一轮扩展就够了，**不引入新的拼图或排版库**。如果排版效果不够好，再评估 Flickr 的 `justified-layout`（MIT），评估结论写进报告。

### 6.2 两种方式

- **自动**：按模板自动挑图。模板有三种：
  - 角色设定：转面 4 张、正面头像、4 个表情；
  - 表情表：正面头像加全部表情，最多 12 张；
  - 造型：每个造型一张，内容是该造型的正面、侧面、背面加正面头像。

  资产不够 4 张的演员（例如新面孔）不显示这个功能。

- **手动**：用户在资产库里勾选的图，最多 16 张。

### 6.3 入口和界面

- 资产库选择工具条上加按钮"拼成角色设定图"，打开一个弹窗：
  - 方式：`GameSegmentedControl` 切换自动 / 手动，自动方式下再选模板；
  - 选项：标注（无 / 中文 / 英文），底色（浅灰 / 白 / 深色），沿用现有选项；
  - 实时预览：1920×1080，用公开预览图渲染；
  - 主按钮"下载 4K"：3840×2160，用原图渲染。
- **谁能做什么**：

  |                    | 游客             | 登录用户 |
  | ------------------ | ---------------- | -------- |
  | 预览自动和手动拼图 | 可以             | 可以     |
  | 下载 4K            | 点了弹出登录引导 | 可以     |

  "会员"就是登录了 Swimmer 账号的用户，现在没有付费会员。

### 6.4 统一的登录引导面板

- 新组件 `SignInPrompt`：标题、三条登录后的好处、"用 Swimmer 账号登录"主按钮、"以后再说"。
  - 用 UIKit `GameDialog`；
  - 关闭后焦点回到触发按钮；
  - 文案见文案稿。
- **出现的时机**：
  1. 游客在 30 秒冷却期内又点了下载（标题换成"再等 {秒} 秒，或者登录"）；
  2. 游客点"下载 4K"；
  3. 游客点"打包 ZIP"。
- 现有的登录弹窗和冷却提示合并进这个组件，全站只留这一种。
- 登录成功后回到原页面、原选择，并且自动继续刚才被拦下的那个动作。
