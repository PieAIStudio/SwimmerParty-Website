# 网站第八轮：最深度的重构

Owner 2026-10-08 的要求：

- 每次升级都会留下冗余，所以要做**最深度**的重构：代码、数据、文档一起来；
- 文档该退役的退役，过去的决策浓缩下来；
- 做完以后仓库干干净净、井然有序、对 AI 特别友好；
- 该删的删，不被过去拖累。老的 API 和外部接口该退役就退役，换成最干净、解耦的做法；
- **重构几轮都可以**。

**时间**（Owner 2026-10-09 改定）：第五到第 7.5 轮的本地工作全部完成、仓库收拾干净以后开始，**在首次发布之前做**。发布放在第八轮之后，一次完成，这样上线的就是清理干净的版本。

- 第 0 节说的"对外行为"，以本地当前行为为准。
- 需要云端的事（SwimmerBackend 生产迁移、Blob、部署）都留到发布时做。社区的后端接口在重构时保持清楚的适配层：本地用模拟实现，以后换成真实后端不需要再改结构。
- 指挥会话会一直往 `media-pack/actors/` 加演员资料、往 `media-pack/library/` 交付素材。第 3.1 节统一演员资料来源时，以 `media-pack/actors/<slug>.json` 为唯一来源，字段保持向后兼容；不动 `library/` 和 `notes/handoffs/`。

**方法**：按 `ai-human-friendly-refactor` 技能（`~/.claude/skills/ai-human-friendly-refactor/`，Codex 侧同名技能）的循环做：

> 先给验证定价 → 定目标 → 画地图 → 选形状 → 加保护 → 一小块一小块改并验证 → 对齐和浓缩 → 收尾

本计划不重复技能内容，只写这个仓库的具体目标，以及技能没覆盖到、这里需要加的部分（第 3 节）。

## 0. 规矩

- 只在 `main` 上做，**一块一提交**：每块改完先过最小相关检查，再提交，提交说明写清这块改了什么、怎么回退。
- **对外行为不变**，除非本计划写明要退役。对外行为指：网址、跳转、分享卡片、下载文件名、JSON 资料结构、署名和授权版本、埋点事件名、项目包格式（MediaFactory 在读）、Blob 路径、登录 cookie 名。
- 删除是结论，不是因为"旧"。每个删除候选都要回答技能里的五个问题：
  - 谁拥有；
  - 有没有人在用；
  - 能不能重新生成；
  - 要不要留存；
  - 是否敏感。

  答不上来就隔离或暂缓，写进报告。
- 发布过的 Blob 原件**永不删除**（第六轮的存档规则）。

## 1. 先给验证定价（技能第 1 步）

- 记录这些命令一次要多久、会不会时好时坏：`pnpm check`、`pnpm verify`、e2e、`pnpm docs:check`。
- 写进 `docs/reference/` 里配置验证的那一页，以后的人直接看，不用重测。
- 如果 e2e 慢或者不稳，**先单独修好**，作为一个有自己证据的目标，再开始重构。

## 2. 地图和契约清单（技能第 2–3 步）

做一份"现状清单"，写进报告。重构的依据是这份清单，不靠印象：

| 类                 | 列什么                                                                         |
| ------------------ | ------------------------------------------------------------------------------ |
| 路由和跳转         | 全部页面、API 路由、308 跳转、sitemap、hreflang                                |
| 外部契约           | 第 0 节那张对外行为清单，逐项写谁在用                                          |
| 代码               | 模块和依赖方向、谁引用谁、没人引用的文件和导出                                 |
| 数据               | 每个事实放在哪：演员资料、版本、授权、文案、资产清单                           |
| 依赖               | `package.json` 每个包的用途和使用位置，没用的、重复的、可换成平台能力的       |
| 脚本               | `scripts/`、`tools/`、`package.json scripts` 各自做什么、还用不用              |
| 配置和环境变量     | 每个变量在哪读、哪个环境有、还需不需要（只列名字，不抄值）                     |
| 文案键             | `messages.source.ts` 里没有页面使用的键                                        |
| 样式               | 没用的 CSS、重复的颜色和间距、绕开设计令牌的写法                               |
| 公开文件           | `public/` 里没被引用的图片和字体                                               |
| 测试               | 每个测试保护什么；重复的、过时的、太慢的                                       |
| 文档               | 每份文档的角色（真相 / 决策 / 导航 / 证据），以及该保留、更新、浓缩、归档还是删除 |
| 云端               | Vercel 项目设置、WAF 规则、Blob 库和路径前缀、PostHog、SwimmerBackend schema   |

发现扫描工具（比如 `knip`）有用，可以用 `pnpm dlx` 临时跑，不加进依赖。工具的结论只是线索，要用技能的标准核实。

## 3. 本仓库的重构目标（含技能没覆盖到的部分）

### 3.1 一个事实只放一个地方

已知的重复：

- **演员资料有两份**：`media-pack/actors/<slug>.json`（给 MediaFactory 和出图用）和 `src/content/actors/<slug>/`（给网站用）。
  - 定一个唯一来源，另一份由脚本生成，或者网站直接读；
  - 生成的文件标明"生成的，不要手改"，并加一条检查：两边不一致就报错。
- **授权和署名**：只在 `src/content/license.ts`（第七轮）。
- **文案**：上线后以 `src/i18n/messages.source.ts` 为准。第三版和第七轮文案稿归档，不再当真相。
- **版本**：只在每位演员的 `releases.ts`。
- **工具列表、事件白名单**：各一个文件。

### 3.2 代码结构

目标形状，具体以第 2 节清单为准，可以调整，理由写进报告：

```text
src/app/          只放路由：拿数据、组装页面，不写业务逻辑
src/features/     按功能分：actors、assets、downloads、community、cast、license、account、analytics
                  每个功能一个 index.ts 对外，功能之间只通过 index 引用
src/content/      纯数据，没有逻辑
src/lib/          与业务无关的小工具
src/server/       只在服务端用的适配器：Blob、SwimmerBackend、AuthKit
```

- **依赖方向**：app → features → lib/content，不反向。用 lint 规则或测试把这条锁住。
- **删除**：
  - 死代码、没人用的导出、旧的 `/kit` 残留、编号（SP-xx）残留；
  - `mock` 模式里已经不用的分支；
  - 重复的下载、打包逻辑（第七轮之后应该只剩一套）；
  - 被第七轮替换掉的导出格式。
- **类型**：外部数据（JSON 资料、项目包、后端返回）各有一份 schema 和类型，校验和类型来自同一个定义。

### 3.3 退役老接口和外部依赖

- 列出所有老网址、老 API、老 Blob 路径、老环境变量、老 WAF 规则，逐项决定"保留 / 跳转 / 退役"：
  - 有外部链接或用户收藏的网址，留永久跳转；
  - 只有站内使用的，直接删。
- `@vercel/analytics` 在第七轮已经删掉，这里确认没有残留。
- 依赖瘦身：没用的包删掉；能用平台或现有能力替代的包，换掉；剩下的钉死版本，按组合规范升级到当前版本。

### 3.4 测试经济

- 每个测试保护一条具体的契约或一个用户路径。重复的合并，过时的删除，太慢的拆分或改成更便宜的层次。
- e2e 只留关键路径：浏览、下载、登录、发布作品、选角单、新面孔投票、授权页。
- 记录重构前后 `pnpm verify` 的时间。

### 3.5 文档：退役、对齐、浓缩

- **计划**：第三到第八轮的计划，状态改成完成，移到 `docs/plans/completed/`。
- **决策浓缩**：从这些计划和 `DESIGN.md` 里，把仍然有效的决策浓缩成一份 `docs/reference/decisions.md`。
  - 每条写：决定是什么、为什么、什么情况下要重新考虑、证据在哪；
  - 例子：做动画不做写实、署名即可商用、slug 永久不变、发布过的原件永不删、只用 PostHog。
  - 被推翻的老决定，只留一句"曾经这样，因为什么改了"。
- **真相文档重写成现状**：`architecture.md`、`release.md`、`DESIGN.md`、`current-work.md` 按重构后的代码重写，不保留过程。
- **报告**：`.devspace-reports/` 只留最近一轮，更早的随归档计划一起处理（按留存规则）。
- **项目包**（`media-pack/`）的说明文档与 MediaFactory 对齐：项目包格式只写一处，另一边只放链接。

### 3.6 对 AI 友好（技能没细写，这里加上）

- **路由文件** `AGENTS.md`：短、准，只说"去哪里找什么"。
- **每个功能目录**一份简短 `README.md`：做什么、入口在哪、对外契约、对应测试。
- **常见改动菜谱**：一页 `docs/reference/how-to.md`，每条三到五步：
  - 加一位新演员；
  - 给演员升版本；
  - 改一句文案；
  - 改授权版本；
  - 审核作品；
  - 加一个埋点事件；
  - 加一个工具名。
- **重复性工作做成项目技能**（`.agents/skills/`），菜谱只放链接。例如"发布一位新演员"这种多步流程。
- **命名**：文件名和目录名一看就知道是什么，不用缩写和内部代号。

### 3.7 安全和卫生

- 扫一遍仓库历史和当前文件，看有没有误提交的密钥。有的话报告给 Owner 处理，不要自己改历史。
- 安全响应头（CSP 等）、上传限速、Owner 接口，各过一遍。
- `.gitignore`、`tmp/`、各种缓存目录、staging 目录：只保留有用的；防止它们以后悄悄回来。

## 4. 做几轮

每一轮按"一块 → 验证 → 提交"推进，顺序如下：

1. 定价，出清单（第 1、2 节）；
2. 数据唯一来源（3.1）；
3. 代码结构和删除（3.2）；
4. 退役老接口和依赖（3.3）；
5. 测试（3.4）；
6. 文档（3.5）；
7. 对 AI 友好（3.6）；
8. 安全和卫生（3.7）；
9. 验收（第 5 节）。

验收没过就回到对应的块，再做一轮。

## 5. 验收

- **零上下文测试**：开一个全新的 AI 会话，只告诉它"读 AGENTS.md"，让它独立完成三件事，不问人、不走错地方：
  1. 改首页一句文案并通过检查；
  2. 把一位新面孔升到 1.0.0（用测试夹具里的假素材）；
  3. 加一个埋点事件。

  记录它在哪里犹豫、读错了什么文件，按记录回头修文档或结构，直到三件事都顺利完成。
- **扫描**：没用的文件、导出、依赖、文案键、公开文件为零；有例外的写明理由。
- **唯一来源**：每个事实一个地方，有一致性检查兜底。
- **对外契约**：第 0 节清单逐项有证据，证明没变或已按计划跳转。
- **验证时间**：`pnpm verify` 时间写进报告，前后对比。
- `pnpm verify`、`pnpm docs:check`、e2e 全过；本地预览给 Owner 看。行为不变，所以发布按正常流程。
