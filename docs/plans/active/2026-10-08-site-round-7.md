# 网站第七轮：署名即可商用、下载重构、作品社区、新面孔投票、选角单、埋点、隐私与条款

Owner 2026-10-08 定的方向：

- 演员**用在任何地方都免费，赚钱的也行**，条件只有一个：署上 **Swim In AI**。目的是让更多人用、顺带宣传网站。
- 让全世界的 AI 爱好者来了就能拿走、用好、做出东西、再发回来。
- 一切往**简洁高效**走，不做复杂系统。

顺序：[第五轮](2026-10-07-site-round-5.md) → [第六轮](2026-10-08-site-round-6.md) → **本轮** → [第八轮深度重构](2026-10-08-site-round-8-deep-refactor.md)。本轮依赖第六轮的 slug 身份、Blob 公开库、版本记录和入库工具。

文案以[第七轮文案稿](2026-10-08-site-copy-round-7.md)为准，它覆盖[第三版](2026-10-08-site-copy.md)同位置的文字。照抄规则不变：缺字先停下来问 Claude。

## 0. 规矩

- 只在 `main` 上做，每一项附证据。
- 不另起第二套方案：
  - 产品分析只用 PostHog；
  - 后端只用 SwimmerBackend（Supabase）；
  - 文件只用 Vercel Blob；
  - 用到 AI 时走 SwimmerAIKit。

  依据是组合规范 `~/PieAI/HQ/docs/canon/pie-product-technology-stack.md`。
- **新依赖只允许 `posthog-js`**（精确版本）。上传用已有的 `@vercel/blob` 客户端直传。确实需要别的，写理由，等 Owner 同意。
- 跨仓库：数据库迁移只在 SwimmerBackend 仓库做（第 8 节）。
- 下面几件事都要 Owner 点头：生产库迁移、新的 Vercel 环境变量、部署。

- **导航四项**：演员 · 作品 · 免费商用 · 工作室（`/actors`、`/works`、`/license`、`/studio`）。

  - `/pact` 并进 `/license#promises`。

## 3. 下载重构

目标：想"拿走"的人只需要记住两件事。

- **一个一个拿，不用登录**；
- **打包拿，要登录**。

| 方式           | 谁能用                       | 入口                                       |
| -------------- | ---------------------------- | ------------------------------------------ |
| 单张图、单段声音 | 所有人；游客每 30 秒一个     | 资产格的下载按钮（不变）                   |
| 懒人包         | 登录                         | 演员页主按钮；资产库下载面板第一项         |
| 全部资产       | 登录                         | 下载面板                                   |
| 自选打包       | 登录                         | 资产库选择工具条；下载面板                 |
| 角色设定图     | 预览所有人可用，4K 要登录    | 下载面板；选择工具条                       |
| 选角包         | 登录                         | 选角单页（第 6 节）                        |

**包里有什么**

- **懒人包**（固定内容）：
  - 正面全身 PNG、正面头像 PNG；
  - `prompt.txt`（角色提示词）；
  - `voice-intro.wav` 和 `lines.txt`（有声音时）；
  - `credit.txt`，加白、黑两版署名 PNG；
  - `README.txt` 和 `license.txt`，内容按文案稿第 6 节。
- **新面孔的懒人包**：试镜照、角色提示词、自我介绍声音、署名卡。
- **全部资产**：这个版本的全部 PNG 和 WAV，加 `lines.json`、`profile.json`、提示词、署名、README、license。

**预先打好包**

- 入库工具 `assets:ingest` 给每个版本生成 `starter.zip` 和 `full.zip`，存进私有 Blob 的 `actors/<slug>/v<版本>/`。
- 下载时先校验登录，再给一个短期签名网址。不再每次现场打包，自选打包除外。
- 文件名例如 `tang-yunqiu_v1.1.0_starter.zip`。

**入口统一**

- 资产库页头只放一个"下载"按钮，打开 `GameDialog` 下载面板，依次列出：
  1. 懒人包，标"从这里开始"；
  2. 全部资产；
  3. 你选的；
  4. 角色设定图。

  每项写清大小和内容。
- 游客点打包类选项，弹统一的 `SignInPrompt`。
- 演员页主按钮改成"领取懒人包"，游客点了也弹登录引导；次链接是"打开资产库 →"。

**合并旧的导出窗口**

现在的导出窗口有三种格式：原图、拼成一张、给某个模型用。

- "原图"并进自选打包；
- "拼成一张"就是角色设定图；
- "给某个模型用"按模型参考图上限挑图的功能，和懒人包重复，**删掉**。对应的 `assets.format.model*`、`assets.model` 文案键一起删。

游客限速和 WAF 的 `rate_limit_api_id` 规则不变。

## 4. 作品区：我们做的 + 大家做的

### 4.1 页面

- **`/works`**：上面是"我们做的"，即现有作品卡；下面是"大家做的"信息流。
  - 排序：最新、最热（按赞数）；
  - 筛选：类型、演员、工具；
  - 筛选条件写在网址参数里。
- **帖子页 `/works/p/<id>`**，内容有：
  - 媒体：图片轮播，或音频播放器，或视频播放器/外链嵌入；
  - 标题、作者、出演演员（链接到演员页）、用的工具；
  - "怎么做的"（可折叠，可复制）；
  - 点赞、举报；作者本人可以删除。
- **演员页**加一条"大家用{name}做的"，最多 8 个，官方样片排前面。资产库里不放。
- **首页**"作品"区放最热的 4 个。

### 4.2 发布

- 登录后才能发，入口是"发布作品"，表单字段见文案稿第 7.2 节。
- **类型和限制**：

  | 类型 | 上传                                       | 外链            |
  | ---- | ------------------------------------------ | --------------- |
  | 图片 | jpg/png/webp/gif，每张 ≤15 MB，最多 6 张   | —               |
  | 声音 | mp3/wav/m4a，≤20 MB，1 个                  | 可以            |
  | 视频 | mp4/webm，≤60 MB 且 ≤2 分钟，1 个          | 可以（长视频）  |
  | 游戏 | 截图当封面                                 | 必须            |
  | 其他 | 封面                                       | 必须            |

- **外链白名单**：YouTube、TikTok、Bilibili、Vimeo、X、Instagram、itch.io、SoundCloud、Spotify。
  - YouTube、Bilibili、Vimeo 用官方嵌入；
  - 其余显示封面和外链按钮，新窗口打开，加 `rel="noopener"`。
- **上传**：用 `@vercel/blob/client` 直传第六轮建的公开库，路径 `community/<post-id>/<n>.<ext>`。
  - 服务端 `handleUpload` 校验登录、类型、大小、数量；
  - 图片缩略图用入库工具现有的图片处理生成，不加新库。
- **演员**至少选一位，从名单里选，新面孔也算。
- **工具**从固定列表里选，也可以写"其他"。列表放 `src/content/tools.ts`，以后只改这一处：
  - ChatGPT、Midjourney、Flux、Stable Diffusion / ComfyUI、Kling、Runway、Veo、Sora、Hailuo / MiniMax、Pika、Luma、ElevenLabs、Suno、CapCut、Blender、其他。
- 两个确认（已署名、遵守规则）必须都勾。

### 4.3 审核：Owner 负担尽量小

- **每个账号的第一条作品**先进待审。Owner 在 `/admin/review` 通过以后，这个账号再发就直接上线（写进 `trusted_authors`）。
- **举报**：同一作品被 3 个不同账号举报，自动隐藏，进待审。
- **Owner 身份**：环境变量 `OWNER_ACCOUNT_IDS`（Swimmer 账号 ID 列表），只在服务端校验。
- **审核页**：两组，待审和被举报；每条一键"通过"或"隐藏"。被隐藏的作品，作者自己还能看到，也能删除。
- 这一版不发通知。页头"审核（N）"就是提醒。
- 如果 SwimmerAIKit 已经有内容审核能力，第一条可以先过 AI 审核再进待审；没有就不做，报告里写清楚。

### 4.4 点赞

登录才能赞，一人一帖一次，可以取消。

## 6. 选角单

- 谁都能用，不用登录；存在浏览器本地（localStorage），最多 12 位。
- **入口**：演员卡片和演员页上的"加入选角单"；页头"选角单（N）"。
- **`/cast` 页面**：
  - 合影预览：所有人按真实身高并排站，用身高数据和全身图按比例缩放，脚底对齐，带身高刻度线；
  - 每人显示名字、一句话、自我介绍播放；
  - 操作：移出、清空、分享、复制名单、复制合并署名、下载选角包。
- **分享**：网址形如 `/cast?a=tang-yunqiu,misha-luo`。别人打开先看；点"存成我的"才覆盖他本地的选角单。
- **选角包**（登录）里有：
  - `lineup.png`，4K 合影；
  - 每人一个懒人包文件夹；
  - `cast.json`；
  - `credit.txt`，合并署名；
  - README。
- **给以后的 AI 选角留接口**：`cast.json` 的结构是 `{ version, story: null, actors: [{ slug, name, reason: null }] }`。

## 7. "同一个人"样片（官方作品）

- 给 4 位可出演演员（唐韵秋、罗米沙、张强、陈伟），每人做 3 张或 3 段样片：用同一个懒人包，换不同工具和场景。
- **工具**：只用 Owner 已经在 Codex 浏览器里登录的。
  - 至少一个图像工具（ChatGPT）和一个视频工具；
  - 没有视频工具就只做图片，报告写明，问 Owner。
- **场景建议**（可以调，记进报告）：一个日常场景、一个动作场景、一个和另一位演员同框。
- **发布**：每个样片作为官方帖子发到"作品"，作者是 SWIMMER PARTY，带"SWIMMER PARTY 出品"标记。
  - "怎么做的"写清楚：用了哪两张图、哪段提示词、什么场景描述；
  - 演员页"大家用{name}做的"里，官方样片排在前面，区块标题用文案稿的"同一个{name}，不同工具"。
- 样片自己也要守免费商用的规则：是动画，不写实。按 `media-pack/checks.md` 看一遍再发。

## 8. 后端：SwimmerBackend

- **按组合规范**：数据放 SwimmerBackend 的 Supabase，新建产品 schema `swimmer_party`。**迁移只在 SwimmerBackend 仓库做**，网站仓库只放需求和调用代码。
  - 规范来源：`~/PieAI/HQ/docs/reference/architecture/swimmer-shared-infrastructure.md`。
- **需求单**：Codex 按 SwimmerBackend `AGENTS.md` 的接单方式写进去，内容见本节附录：
  - 表：`posts`、`post_media`、`reactions`、`reports`、`trusted_authors`。
  - **访问方式**：网站服务端带用户身份走 RLS，或者走 SwimmerBackend 的受控 RPC；不把表直接暴露给浏览器。按 SwimmerBackend 的 schema 登记规则写清 owner、暴露方式、RLS、迁出路径。
  - **账号注销**：加进 SwimmerBackend 的注销覆盖（account closeout coverage）。注销时删除该用户的帖子、媒体索引、点赞、投票、举报；Blob 里的文件由网站的清理任务按索引删除。
  - **显示名**：用 Swimmer 账号的公开显示名，没有就显示"Swimmer"加短 ID。`swimmer_party` 里不存 email。
- **流程**：
  1. Codex（网站）写需求；
  2. 开一个 SwimmerBackend 会话，实现迁移、RLS 和测试；
  3. 先在本地和 staging 验证；
  4. **生产迁移要 Owner 同意**，由 SwimmerBackend 会话执行。
- **本地开发**：用现有的 `mock` 账号模式，加一个内存版数据实现，e2e 不依赖远程库。

**附录：字段**

- `posts`：
  - `id uuid pk`；
  - `author_id uuid`（core 用户）；
  - `kind`：image / audio / video / game / other；
  - `title`（≤120 字）、`description`（≤2000，可空）、`recipe`（≤4000，可空）；
  - `tools text[]`；
  - `actor_slugs text[]`（至少 1 个）；
  - `external_url`（可空）；
  - `status`：pending / published / hidden / removed；
  - `is_official bool`；
  - `like_count int`；
  - `created_at`、`updated_at`、`published_at`。
- `post_media`：
  - `id`、`post_id`、`n`；
  - `kind`：image / audio / video / cover；
  - `blob_url`、`width`、`height`、`duration_s`、`bytes`、`created_at`。
- `reactions`：
  - `user_id`；
  - `target_type`：post / actor；
  - `target_id text`；
  - `kind`：like / vote；
  - `created_at`；
  - 主键是 user_id、target_type、target_id、kind 四列。
- `reports`：
  - `id`、`post_id`、`reporter_id`、`reason`、`note`（可空）、`created_at`；
  - `(post_id, reporter_id)` 唯一。
- `trusted_authors`：`user_id pk`、`approved_at`、`approved_by`。

## 9. 埋点：PostHog

- **依据**：组合规范第 8.1 节，全组合只用 PostHog。**删掉 `@vercel/analytics`**。
- **密钥**：用已有的共享项目，不新建项目，也不用个人 API key。
  - 本地文件：`~/PieAI/.secrets/posthog/shared.public.env`，变量是 `POSTHOG_PROJECT_KEY`、`POSTHOG_HOST`；
  - 网站里映射成 `NEXT_PUBLIC_POSTHOG_KEY`、`NEXT_PUBLIC_POSTHOG_HOST`；
  - 本地按 `~/PieAI/.secrets/README.md` 的做法接：框架默认的环境文件做软链；
  - Vercel 里的生产变量由 Owner 设置，或在 Owner 同意的发布步骤里设置。
- **写法**：照官网 `~/PieAI/SwimInAI-Website/src/lib/analytics.ts` 和 TuringPact `src/services/product-analytics/`，写一个薄适配器 `src/features/analytics/`：
  - 事件白名单，有类型检查；
  - 每个事件都带 `app=swimmerparty` 和 `locale`；
  - 不用 cookie（内存持久化），不自动采集，不录屏；
  - 本地和测试默认关闭；
  - 埋点失败不影响页面；
  - `posthog-js` 动态加载。
- **事件**（只有这些）：

  | 事件                   | 属性                                                                                         |
  | ---------------------- | -------------------------------------------------------------------------------------------- |
  | `page_viewed`          | `page`：home / actors / actor / assets / works / post / license / studio / cast / privacy / terms |
  | `actor_viewed`         | `slug`、`status`                                                                             |
  | `voice_played`         | `slug`、`slot`                                                                               |
  | `asset_downloaded`     | `slug`、`kind`（image / voice / starter / full / selection / sheet / cast / credit_kit）、`signed_in` |
  | `sign_in_prompt_shown` | `trigger`（cooldown / pack / sheet / post / like / vote）                                    |
  | `sign_in_started`      | `trigger`                                                                                    |
  | `cast_changed`         | `action`（add / remove / clear）、`size`                                                     |
  | `cast_shared`          | `size`                                                                                       |
  | `post_started`         | `kind`                                                                                       |
  | `post_published`       | `kind`、`actor_count`、`has_recipe`                                                          |
  | `post_liked`           | —                                                                                            |
  | `post_reported`        | `reason`                                                                                     |
  | `actor_voted`          | `slug`                                                                                       |
  | `credit_copied`        | `place`（license / assets / cast）                                                           |
  | `filter_used`          | `page`（actors / works）、`field`                                                            |
  | `share_clicked`        | `page`                                                                                       |
